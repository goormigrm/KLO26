## 5. 캐릭터 그래픽 — 무료로 "영상처럼"까지 갈 수 있나

### 5.1 지금 캐릭터가 왜 지점토로 보이나

DESIGN 7.1 의 결정 그대로다 — 구(머리) + 캡슐(몸·팔·다리) 프리미티브, 머리:몸 1:2.2 대두, `MeshToonMaterial` 3단, 점 눈. 코드 애니메이션(사인 스윙). **의도한 스타일**이었지만 영상 옆에 두면 세 가지가 튄다: 비율(대두), 질감(무광 단색), 모션(관절 없는 스윙).

### 5.2 선택지

| 옵션 | 방법 | 결과 | 비용 | 위험 |
|---|---|---|---|---|
| **A. 프리미티브 개선** | 비율을 6.5등신으로, 목·어깨·손·무릎 추가, 머리카락 메시 4종, 얼굴 텍스처(눈·눈썹·입), `MeshStandardMaterial` + 살짝 광택, 팔꿈치·무릎 관절 굽힘 | "세미 리얼 캐주얼". 영상 수준은 아니다 | 2~3일 | 낮음 |
| **B. 무료 실사 캐릭터 + 모션캡처 (권장)** | Adobe **Mixamo** 캐릭터(실사 비율 인간 모델, 유니폼 없음) + Mixamo 애니메이션 → Blender(무료)에서 glTF 로 → three.js `SkinnedMesh` + `AnimationMixer`. 한 뼈대에 `SkeletonUtils.retargetClip` 으로 통일. 유니폼은 텍스처 교체 | **영상에 가장 가깝다** — 8등신·모션캡처 달리기·다이브 | PoC 4~5일 + 전면 5~7일 | 라이선스(5.3) · 리타게팅 발 미끄러짐 · 파일 크기 |
| C. CC0 로우폴리 (Quaternius · Kenney) | 완성된 캐릭터 + 애니 GLB 를 그대로 | 스타일라이즈드(각진 로우폴리). "현실적"과 반대 방향 | 1~2일 | 낮음 |

### 5.4 옵션 B 의 구현 설계

**파이프라인** (`tools/char/`)

1. Mixamo 에서 캐릭터 1종(실사 남성, 유니폼 없는 기본 복장) + 애니메이션을 FBX 로 받는다. 애니 목록: Idle · Walking · Running · **Sprint(Running Fast)** · Soccer Pass · Soccer Kick(Strike) · Soccer Header · Soccer Tackle(Slide) · Soccer Trip/Fall · Goalkeeper Dive L/R · Goalkeeper Catch · Getting Up · Throw In · Celebration ×2. (정확한 이름은 Mixamo 검색으로 확정 — FAQ 는 목록을 안 준다.)
2. Blender 스크립트(`tools/char/fbx2glb.py`, 무료)로 **한 뼈대**에 애니를 모아 GLB 하나로 굽는다. Draco 또는 meshopt 압축. 목표 ≤ 8 MB.
3. three.js: `GLTFLoader` + `SkeletonUtils.clone` 으로 22명 복제(뼈대 공유 불가 → 각자 `SkinnedMesh`), `AnimationMixer` 22개. 클립은 하나의 `AnimationClip` 배열을 공유.

**sim ↔ 애니 매핑** (렌더 전용 — `src/core` 는 그대로)

| sim 상태 | 클립 | 파라미터 |
|---|---|---|
| `ACT_RUN` speed < 0.5 | Idle | — |
| 0.5 ~ 4.5 m/s | Walk ↔ Run 블렌드 | speed |
| ≥ 4.5 · `sprint` | Sprint | 재생 속도 = speed / 8 |
| `ACT_KICK` (6틱) | Pass 또는 Strike (홀드 파워로) | 0.32 초로 늘려 재생 (지금 `kickT` 방식) |
| `ACT_SLIDE` | Slide Tackle | — |
| `ACT_FALLEN` | Trip → Getting Up | actT |
| `ACT_DIVE` (GK) | Dive L/R (lateral) | 12틱 비행에 맞춤 |
| `holdT > 0` (GK) | Catch → Hold | — |
| `throwing` | Throw In | — |
| `phase === 'goal'` 득점자 | Celebration | 시드로 2종 |

블렌딩은 `mixer.clipAction(...).crossFadeTo(next, 0.15)`. 발 미끄러짐은 클립 재생 속도를 sim 속도에 맞춰 줄인다(Running 클립의 원래 속도를 재서 `rate = speed / clipSpeed`).

**유니폼·번호·구단 색**

- Mixamo 캐릭터의 옷 텍스처를 **캔버스로 다시 그린다**: 상의·바지·양말 영역 마스크(한 번 만들어 둔 UV 마스크 PNG) 에 구단 색·등번호·이름을 채운다. 지금 `kits.ts` 의 단색 규칙(홈 구단 색·원정 흰색·GK 별색)을 그대로 쓴다.
- 얼굴·피부: **실존 선수를 닮게 하지 않는다**(DESIGN 7.1 유지). 피부색도 반영하지 않는다(데이터 없음). 머리 모양 4종은 Mixamo 캐릭터 2~4종을 id 해시로 배정하는 것으로 대신한다.
- 키·몸무게: `h/180` 배율은 뼈대 스케일로, 몸무게는 어깨·허리 뼈 스케일 ×(1 + mass·0.06).

**성능**

- 캐릭터 1명 8~12k 삼각형 × 22 = 약 220k. 내장 GPU 에서 60 fps 는 스킨드 메시 22개면 가능하지만 **그림자맵 두 번 그리기**가 병목 → 그림자는 공 주변 40 m 만(3장). 해상도 스케일 0.75 옵션 유지.
- 첫 로딩: GLB 8 MB → 로비에서 미리 받아 두고(`link rel=preload`), 받는 동안 찰흙 모드로 시작 가능.

**되돌릴 수 있게**

- 설정 `graphics: 'clay' | 'real'`. `buildPlayer` 는 인터페이스(`PlayerRig`)만 남기고 `player3d.ts`(찰흙) · `playerReal.ts`(실사) 둘 다 구현. 리플레이·카메라·HUD 는 공유.

### 5.5 판단

- **영상 수준(EA 의 스캔 얼굴·전용 모션캡처)은 무료로 불가능**하다. 실존 선수 얼굴은 초상권 문제도 있어 애초에 하지 않는다.
- **"실사 비율 + 모션캡처 달리기 + 유니폼·조명"까지는 무료로 간다** — 옵션 B. 영상 옆에 놓았을 때 "게임 같다"는 인상의 8할은 비율과 모션에서 온다.
- 라이선스 표(5.3)에서 Mixamo 가 재배포 가능으로 확인되면 B 로 간다. 아니면 C 를 실사풍에 가장 가까운 CC0 캐릭터로 골라 같은 파이프라인을 쓴다(파이프라인은 동일).
- A 는 B 의 PoC 가 실패했을 때의 대안이 아니라 **P0 와 함께 바로** 할 수 있는 저비용 손질(비율·재질) — B 를 기다리는 동안 인상을 올린다.
